## 2 标签重配（v2，2026-10-23）

旧版的「目的/动作」是从上游 category 机械映射的，两个系统性错误：
`技术/功能类 → 转人工`、`账单 → 账号`，结果 **转人工 占 71%**。
现在按 `cs-decision/ACTIONS.md` §3 策略表重配：

| 触发 | 旧 | 新 |
|---|---|---|
| 账单问题 | 账号 / 转人工 | **发票 / 安抚话术** |
| 技术问题、功能用不了、页面加载不出来、App 闪退 | 询问功能 / 转人工 | **询问功能 / 安抚话术** |
| 账户问题、账户相关、无法登录、注销、取消订阅、导出数据、改绑手机号 | 账号 / 转人工 | **账号 / 安抚话术** |
| 退款问题一直没解决 | 退款 / 转人工 | **退款 / 退款** |
| 物流问题一直没解决 | 物流查询 / 转人工 | **物流查询 / 补发** |
| 这事很急（模糊） | 其他 / 转人工 | **其他 / 安抚话术** |
| 我在考虑换一家（挽留） | 其他 / 转人工 | **其他 / 发红包** |
| 就是我、生日活动、有个事想问问（模糊） | 其他 / 转人工 | **其他 / 安抚话术** |

`转人工` 只留给：威胁投诉/曝光/监管/12315、点名要上级、二次以上投诉、辱骂失控、明确要人工、极模糊到无法处理。

重配后 `安抚话术` 变成多数类（480/791）。为免“永远答同一类”也能拿高分（多数类基线就是它的占比），
再按**确定性等距抽样**把最大的动作类压到占比 ≤ 25%：安抚话术 480 → 103。
抽样只删行、不改标签；eval 不抽样（评估集保持真实配比）。

## 4 格式

每行一个 JSON：

```
{"state":{"message":"客户消息"},"questions":{"情绪":{"type":"choice","criteria":{...}},"目的":{...},"动作":{...}},"gold":{"情绪":{"probabilities":{"不满":0.9,...}},...}}
```

`gold` 是分布：命中项 0.9、其余均分 0.1。

## 5 已剔除的东西（留痕）

上一版 `laya-cs-v4..v8` 的 train 里各有 **80 行**来自 `waimai_10k`（70 行）与 `ChnSentiCorp`（10 行）的挑拣；
这两个 HF 仓库**都没有许可证**（卡片是空模板、`dataset_infos.json` 的 `license` 为空），
因此这 80 行已从分发物中剔除。剔除后 `v4` 与手标集完全相同，所以版本历史（v4-v8）不再随包分发。

```

<包>\4-环境\runtime\python\python.exe -m laya.train_cli --data <本目录>\train.jsonl --eval <本目录>\eval.jsonl --base <包>\model\laya-v8 --out <临时目录> --epochs 4 --micro-batch 8 --grad-accum 8 --loss rlcd --max-len 512 --dry-run
```

读数：`eval 115 rows read, 345 valid items` / `train 414 rows read, 1242 valid items, skipped: {}` /
`1118 train item(s) ... 72 optimizer updates over 4 epoch(s)`。
**零条被跳过** ⇒ schema 全对。`laya` 包在 `4-环境/third_party/laya` 里，不需要另装；
注意 `laya-train` 这个命令名不保证在 PATH 上，用上面的 `python -m laya.train_cli` 等价。

> eval 不抽样、保持原切分，所以它的动作分布与 train 不同（`补发` 偏多、`退款` 为 0）——
> 按动作报准确率时要连同这一点一起读，别把类别分布差异当模型能力。
